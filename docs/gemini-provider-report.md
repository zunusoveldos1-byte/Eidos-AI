# Gemini API в Eidos

В «Настройки → Модель» добавлен провайдер «Gemini API — облако».
Показываются отдельные поля модели (по умолчанию `gemini-2.5-flash`) и ключа
с маскированием. Ключ сохраняется только в Windows Credential Manager;
JSON-настройки содержат лишь имя модели. Пустое поле оставляет прежний ключ.
Удаление сохранённого ключа доступно в «Подключениях → Удалить секрет → gemini».

Справа скрываются запуск/загрузка Ollama и диагностика локального оборудования.
«Проверить ключ» сохраняет выбранные параметры и проверяет доступ к метаданным
модели через GET. Успех этого запроса не доказывает наличие квоты генерации.
«Проверить ответ и tool calling» проверяет генерацию и запрос `calendar_list`
через существующий диагностический сценарий. Обе операции выполняет AgentWorker.
Внешние запросы отправляются только после явного запуска пользователем.

Новый `GeminiProvider` использует REST GenerateContent с асинхронным httpx
в существующем QThread. Системные сообщения передаются как `systemInstruction`,
история — как `contents`; роли и ответы инструментов преобразуются в формат
Gemini. JSON Schema инструментов передаётся через `parametersJsonSchema`.
API-ключ используется только в `x-goog-api-key`, не в URL или теле запроса.
Транспорт ограничивает ответ 4 MiB и поддерживает отмену до получения заголовков.
Ошибки 400/401/403/404/429 показываются без тела vendor-ошибки и без ключа.

Ответы `functionCall` возвращаются общему Harness. Валидация аргументов,
разрешения, подтверждения, защита повторов и лимит шагов остаются общими
для Gemini/Ollama/OpenAI. Результаты инструментов отправляются обратно как
`functionResponse`. Оригинальные части ответа, включая thought signatures,
сохраняются на время текущего цикла инструментов; не попадают в UI или
постоянную историю. Обрезанный вызов инструмента не выполняется.

Изменены: agent/settings.py, secrets.py, providers.py, service.py, controller.py,
skills.py; ui/pages/assistant.py, settings_layout.py, assistant_bindings.py,
main_window.py; все пять каталогов локализации. Добавлены agent/gemini.py и
tests/test_gemini_provider.py, tests/test_gemini_ui.py. Отдельный SDK устанавливать
не требуется: httpx уже входит в зависимости агента.

Проверено: преобразование system/history/tools и возврат подписанных частей,
цикл вызова инструмента через Harness, отказ при отсутствии ключа/секретах,
отмена до HTTP-заголовков, ошибки API, проверка метаданных модели,
маскирование и сохранение ключа вне JSON. Во время фоновой проверки GUI-таймер
продолжает работать. Настоящее Windows-окно Gemini показано и безопасно закрыто,
код процесса 0; изображение `docs/screenshots/gemini/model-native.png`.
Полный набор после изменений: **397 тестов прошли за 104,36 секунды**.
Лог: `.cache/gemini-tests.log`; `compileall` также прошёл.
Живой запрос в Gemini не выполнялся: пользовательский API-ключ не предоставлен.
Доступность конкретной модели, региона и квоты проверяется собственным ключом
через кнопки приложения; автоматического переключения модели нет.

Протокол сверён с официальными источниками:
[GenerateContent и FunctionDeclaration](https://ai.google.dev/api/generate-content),
[метаданные моделей](https://ai.google.dev/api/models),
[Function Calling](https://ai.google.dev/gemini-api/docs/function-calling).
