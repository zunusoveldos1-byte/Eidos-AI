# Live voice latency benchmark

Замеры автоматически работают в голосовом конвейере и пишутся в logger
`eidos.voice.latency`, который наследует существующие обработчики Eidos.
Включать отдельный режим или запускать benchmark-скрипт не требуется.

Пример формата (это иллюстрация, не реальные измерения компьютера):

```
INFO eidos.voice.latency: STT: 38ms | LLM: —
INFO eidos.voice.latency: STT: 38ms | LLM: 140ms
WARNING eidos.voice.latency: STT: 838ms | LLM: — | slow STT (>500ms)
```

STT — от последнего аудиофрагмента, который VAD определил как речь,
до готового текста. Используется perf_counter в аудиоколбэке и worker.
Включает ожидание тишины, завершение приёма фразы, очередь оставшихся PCM-фрагментов
и распознавание/финализацию. Точность границы фразы ограничена размером аудиоблока
и VAD; это не эталонная ручная разметка конца речи. После streaming-обновления
SILENCE_SECONDS=0.65: STT-response обычно будет больше 650 ms даже при быстрой
финализации Vosk.
Для разделения этих затрат сохранены отдельные stt и stt_finalization samples.
Для предоставленного готового аудио (например, wake buffer) без временной метки
конца речи STT считается от передачи аудио распознавателю до готового текста.

LLM — от вызова OllamaProvider.chat до первого непустого текстового фрагмента
потока: включает HTTP, загрузку модели, обработку промпта и первый текстовый токен.
Пустые фрагменты, thinking и tool_calls без текста не считаются первым токеном.
Первый токен учитывается и в последней JSON-строке без завершающего newline.
Полная генерация ответа не используется вместо first-token latency.
Точное значение сохраняется в provider.metrics['first_token_ms']; вывод округлён
до целых миллисекунд. Для команды без обращения к Ollama LLM остаётся «—».
Многошаговый агент может вывести отдельный LLM-замер для каждого запроса к модели.

Порог предупреждения: строго больше 500 ms для нового измеренного этапа.
Логирование происходит один раз на готовый STT и один раз на первый текстовый
фрагмент каждого LLM-запроса; нет таймеров или опроса в GUI. ContextVar связывает
STT и LLM одного голосового запроса, включая asyncio, и сбрасывается в finally.
Логи содержат только названия этапов и длительности — без речи, ответов, ключей.
Метрика stt_response и существующая llm_first_token также поступают в bounded
StageMetrics для p50/p95. История ограничена 256 значениями на stage/mode.

Проверки: tests/test_voice_latency.py (порог, изоляция запроса, точная граница
измерения и отсутствие приватного содержимого в логе), test_ollama_transport.py
(первый токен и завершение потока), streaming/voice/continuous voice tests.
Используются заглушки и локальный протокольный сервер, без реальных обращений
к AI, голосовых записей или обещаний конкретной скорости оборудования.
