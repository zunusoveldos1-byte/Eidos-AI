# Проверки персонального ассистента Eidos — 10.10.2026

Рабочий ноутбук: i5-12450HX (8 ядер / 12 потоков), RAM 15,73 GiB,
RTX 3050 Laptop 6144 MiB VRAM, Intel UHD, NVIDIA driver 617.42.
Замеры без serial/UUID — `hardware.json`. Первоначальная доступная RAM около
0,5 GiB, позднее 1,59 GiB. Portable Ollama 0.40.2 из официального GitHub release;
архив 1 468 085 195 байт. Основная модель — `qwen3:4b-instruct-2507-q4_K_M`, 2,5 GB, контекст 4096.
Выбран точный Instruct-тег: общий `qwen3:4b` оказался Thinking-версией 2507. Облегчённый вариант 1.7B / 2048 рекомендован, отдельно не скачивается.

## Автоматические и нативные проверки

- 77 тестов pytest проходят с настоящим Windows Qt platform plugin (6,96 с)
  и offscreen (7,24 с). После исправления компоновки повторно прошли
  16 тестов UI (2,91 с), затем 8 проверок UI/transport (7,08 с).
  Unit-тесты не загружают AI-модели.
- Ollama transport: локальный тестовый HTTP-сервер проверяет отмену и дедлайн
  во время ожидания первых headers, сборку NDJSON tool calls и отказ при
  обрыве ответа до done. AsyncClient работает внутри worker-owned loop.
  GUI обработчики не вызывают asyncio.run().
- Команды, сохранение настроек, старые голосовые workers / ошибки / отмена,
  GUI-сигналы, настройки и исходные пять страниц сохранились.
- Аргументы tools: неизвестные/лишние поля, bool вместо integer, диапазоны,
  разрешения, отмена до действия, дедлайн, максимум шагов, неподтверждённый
  результат, запрет повторного side effect, только безопасный read retry.
- Недоверенная страница не может вызвать новое действие без подтверждения;
  данные не расширяют allowlist. Локальные URL и служебные IP отвергаются.
  Web reader соединяется с проверенным публичным IP и проверяет TLS hostname,
  чтобы повторное DNS-разрешение не меняло границы доступа.
- Память: SQLite persistence, FTS, изменение/удаление, source/date,
  инкогнито/отключение, фильтр секретов и выключение даже при сбое настроек.
  Точные значения credential keys без узнаваемого формата также не сохраняются;
  tool result очищается перед передачей модели.
- TXT/MD/DOCX/XLSX/PDF: реальный roundtrip библиотек, русские символы,
  новая версия сохраняет исходные байты, запрещён выход из выбранной папки.
- Календарь: подтверждение до записи, CRUD, UTC / Asia/Bishkek,
  отказ несуществующего местного времени в DST gap.
- Боты: одновременно user И channel allowlists, лимиты, запрет вложений,
  резервирование доставки до send, отсутствие retry после неизвестного исхода,
  запрет повторной входящей задачи и удалённых Windows-команд по умолчанию.
- UI закрывается во время worker-задачи / ожидающего подтверждения;
  побочного календарного изменения после закрытия не возникает.
- Полная цепочка Voice UI → fake recorder/STT → общий harness → fake Windows
  tool → реальный Qt-сигнал ответа; модель не вызывается для этой команды.
- `python -m eidos --smoke-test`: настоящий GUI открылся и закрылся без записи;
  Windows нашёл 14 входных устройств. Импорты сохраняют тяжёлые engines lazy.
- compileall и pip check проходят. Wheel содержит agent modules и 22 ресурса;
  без SQLite, кешей и portable runtime. При первом сборочном вызове не хватало
  setuptools в venv; backend установлен, сборка выполнена заново. Позднее
  pip отказал в доступе к sandbox Temp; build temp перенесён в .cache/pip-temp,
  установка metadata и сборка прошли. Это устранённые ограничения среды.

## Реальные проверки внешних / Windows API

PyCaw 20260927: GetSpeakers().EndpointVolume, чтение громкости 80% / mute False,
установка текущих значений и контрольное чтение подтвердили результат.
Windows Credential Manager: запись/чтение/удаление временного тестового секрета
через явный WinVault backend. Никакие реальные пользовательские токены не вводились.
Web reader прочитал https://docs.ollama.com/api/chat (4293 символа результата).
Ollama ответы, tool calling, GPU и память: отдельный `agent-benchmark.json`.

## Измерения локальной модели

Фактический тег `qwen3:4b-instruct-2507-q4_K_M`, digest `0edcdef34593`,
Q4_K_M / 4.0B / контекст 4096. Ollama `/api/ps`: 3 178 149 969 байт
размещения модели в VRAM (2,96 GiB), весь размер в GPU; runner log:
37/37 слоёв offloaded. Первоначальный CUDA runtime уже запускался во время
диагностики: первый запрос ниже включает загрузку этой модели в память,
но не является измерением нового компьютера с пустым CUDA cache.

| Проверка | Время |
|---|---:|
| Первый ответ «Здравствуйте!», включая load 5,04 с | 5,745 с |
| Структурированный `calendar_list` с arguments={} | 0,529 с |
| Два предложения о Python list / tuple (77 output tokens) | 1,916 с |
| Полный harness: инструмент → пустой календарь → ответ | 1,690 с |
| Отмена длинной генерации, запрос cancel через 0,5 с | 0,531 с |

Пик суммы RSS / рабочих наборов daemon + backend descendants: **1050,42 MiB**
(семплирование ~0,1 с; это сумма рабочих наборов, не уникальные физические страницы).
Доступная системная RAM: до 1,96 GiB, минимум 1,02 GiB. Свободная VRAM:
5436 → 2307 MiB; это показания всей GPU, включая другие процессы.
Свободный диск перед измерением: 99,27 GiB. Эти короткие пробы не доказывают
качество любых задач или скорость совместно с Whisper / камерой / OCR.

Первый пробный generic-тег оказался Thinking-моделью; его холодный GPU-запуск
превысил старый read timeout 30 с. Ошибка сохранена в
`agent-benchmark-first-attempt.json`; его RSS некорректен для полной модели,
поскольку ранний sampler не включал llama-server. После диагностики выбран
точный Instruct-тег, sampler включает backend, а AsyncClient в worker даёт
отмену до первых headers. Промежуточная Thinking-модель удалена из Ollama:
в кеше оставлен только проверенный Instruct. Облегчённая 1.7B не скачивалась.
Реальный ответ повторно прошёл через GUI-worker и сохранён на снимке диалога.

Telegram / Discord / OpenAI / Brave API требуют данных пользователя. Их формы,
проверки и адаптеры реализованы; успешный внешний вход/отправка не заявляются.
Unit-тесты используют mock API. Windows Settings URI проверяется кодом запуска
и наблюдением процесса; запуск реального окна Settings в этой сессии не тестировался.
Процесс разрешённого EXE подтверждается созданием процесса; появление окна
не обещается. Внешний календарь — интерфейс, не готовая синхронизация.

## Снимки

`screenshots/agent`: семь новых вкладок и onboarding, реальный Qt.
`screenshots/agent-small`: 800×600 / DPR 1.25.
`screenshots/agent-small150`: 800×600 / DPR 1.5 (1200×900 пикселей).
Горизонтальная прокрутка 0, content width равна viewport width во всех вкладках.
Вкладки имеют собственную вертикальную прокрутку и tabbar со стрелками в узком окне.
Onboarding прокручивается, кнопки «Пропустить»/«Начать» остаются видны.
Нижний декоративный маскот скрывается в невысоком окне, сохраняя доступ к «Настройкам».
Снимок с ответом модели снимается только после реального прохождения UI-worker.

Реальная речь с микрофона, фактическое распознавание Whisper и услышанное
воспроизведение в этой задаче не проверялись. Предыдущая проверка TTS получила
MP3, QtMultimedia дошёл до EndOfMedia и удалил временный файл; это не подтверждает,
что звук был услышан. Совместная нагрузка LLM + Whisper + камера/OCR не измерена.
Vision/OCR-зависимости не устанавливались. Память не переобучает модель.
