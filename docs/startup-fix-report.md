Воспроизведено два отдельных сбоя:

- Команда `python` в текущем окружении указывала на недоступный псевдоним
  `AppData/Local/Microsoft/WindowsApps/python.exe`. Интерпретатор проекта
  `.venv/Scripts/python.exe` исправен. Добавлен `start_eidos.cmd`, который
  запускает приложение этим интерпретатором из правильного каталога и
  сохраняет сообщение об ошибке на экране при неудаче.
- Штатный запуск доходил до создания окна и падал при `showMaximized()`:
  faulthandler сообщил Windows access violation, код процесса `-1073740771`.
  Изоляция показала: чтение Windows MSG исправно, сбой возникал при вызове
  `super().nativeEvent(...)`. Обработчик только наблюдает сообщения и теперь
  возвращает `(False, 0)`, оставляя стандартную обработку Qt. Чтение указателя
  разрешено только для типов `windows_generic_MSG` и `windows_dispatcher_MSG`.
  Снимки сессии при сне и завершении сеанса сохранены.

Также обновлён `scripts/check_runtime.py`: он проверяет зависимости PCM/VAD
и обрабатывает результат TTS как PCM в памяти, вместо ожидаемого ранее пути.
